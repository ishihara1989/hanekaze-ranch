# 2D・3Dレース観戦

## 全6場の2D観戦と背景素材

`/race-2d-preview.html` に芝・ダート2400m・12羽の試走を用意した。「競走場」で天空神殿、王宮都市、熱帯密林、砂浜公園、秘境遺跡、山岳廃坑を切り替える。`?track=oukyu` などのURLでも選べる。牧場の `Ranch.simulateField` で各場の走行記録を一度作り、2Dと3Dで同じ記録を再生する。各場の比較には同じ12羽を使う。試走ページは独立したメモリ上の牧場を使い、セーブしない。羽色と額羽の組合せはプレビュー用に変更している。

本編のレース観戦は正式な2D画面を標準とする。週報の「観戦する」、チョコボ詳細の「これまでのレース → 結果・観戦」、牧場手帳の「報告」から開く。競走場情報がない古い走行記録も2Dの図形背景で表示する。走行記録自体がない戦績は結果のみを表示する。

「2D / 3D」の切替では再生位置・停止状態・再生速度・注目羽・カメラ・実況音声・描画ピッチを保つ。本編の「動き」は描画ピッチ1×・1.5×・2×に対応する「ゆったり / ふつう / きびきび」で、既定は「きびきび」。既に表示中の方式を選んでも再生は中断しない。読み込みに失敗した場合はその方式を選び直して再試行できる。観戦の操作で確定結果と保存データを変更しない。

背景は内蔵 image_gen で全6場を生成した。Google Imagenの接続がないため、ユーザー確認のうえ代替を使用。`assets/race-2d-backgrounds/*-v1.png` に1774×887の画像6枚を保存し、`prompts-v1.json` に生成プロンプト、`manifest-v1.json` に寸法と各場の対応を残した。素材一覧は `/race-2d-backgrounds.html`。天空神殿は雲海と浮遊神殿、王宮都市は宮殿と城下町、熱帯密林は巨大樹と滝、砂浜公園は海とヤシ、秘境遺跡は古代の石造アーチと山並み、山岳廃坑は岩山と坑道。

`race-2d-graphics.js` は画像を緩やかに横へ流し、交互に水平反転して同じ端同士を接続する。画像に柵・走路・ゲート・ゴールは含めず、コースの形状はCanvasで描く。素材を読み込めない場合は従来の図形背景を使う。ダートは砂の色を場ごとに分け、細かな砂粒、小石、轍と走行中の砂ぼこりを重ねる。

`race-viewer-2d.js` はCanvas 2Dのみで描画する。既存の `assets/chocobo-sprite-study/v5/` にある本体10色と額羽6色を重ねる。元素材は右向き。左回りは右向き、右回りは水平反転して左向き。試走ページで右回りの確認もできる。旧記録の額羽に6色以外の値がある場合は近い既存色を使う。

ラストスパートには `v5/spurt/` の専用8コマを使う。首を低く伸ばし、翼を後方へ広げ、目を細めた表情。本体10色・額羽6色を通常走行と同じコマ・座標で重ねる。記録が「スパート」のときと残り400m以内の競り合い・羽混み・進路変更で切り替え、「粘り」「余力温存」・入線後・停止・表彰では通常姿勢へ戻す。巻き戻し時も記録から姿勢を選ぶ。両モーションを表示開始前に読み込み、画像を共有キャッシュする。素材プレビュー `/chocobo-sprite-preview.html?motion=spurt` で姿勢と全差分を同期比較できる。原画・マスク・金色の光沢は内蔵 image_gen で作成し、プロンプトは `assets/chocobo-sprite-study/PROMPTS-spurt-v1.json` に保存。

`race-2d-course.js` で共通フレームのメートル座標を、カメラ位置の接線と外向き法線へ投影する。前後方向は全羽・路面・柵・旗・ゲート・ゴールに描画ピッチの倍率を一律に掛ける。連続した横位置を再現し、外側の羽を手前へ重ねる。横50mの奥行きを圧縮し、画面で分かるようカーブの縦方向を強調する。小さい画面では奥行きの圧縮率を緩め、内寄せや進路変更が見える幅を確保する。全景では倍率に合わせて画角を広げる。ゲート・ゴールは実際のコース座標に固定する。

描画ピッチ1×では左右2歩＝8コマの1周期を20mに対応させる。20m/sなら1秒で8コマ、40m/sなら半秒で8コマ。外側のカーブの弧長と横移動を走行記録から積算するので、内外のレーンでも物理的な20mごとに1周期になる。

発走直後の加速中は、巡航と同じ足のテンポで描く。走行記録の最初の12秒から速度が落ち着いた区間を探し、その直後の巡航区間の歩行周期を加速中にも使う。巡航に移る時点のコマと周期が連続になるよう、以降の足の積算距離に一定のオフセットを保つ。実際の位置・柵との相対移動・砂ぼこりは元の走行距離に従う。描画ピッチの倍率は加速中と巡航で共通。ゲート待機中と停止中は静止し、巻き戻しでも同じ時刻には同じコマを表示する。

スピード感のための「描画ピッチ」は既定2×、1×・1.5×・2×を選べる。走行距離にこの倍率を掛けてスプライトを進める。20m/sで2×なら16fps、8コマは0.5秒（実距離10m）。時計、実際の羽の位置、着順と入線時刻は変えない。「再生速度」とは独立した設定。

柵の支柱は見た目の距離で5m間隔。`sceneryPattern` は倍率に応じた間隔で固定のコース座標を並べ、カメラに依存する移動補正は加えない。2×ではその0.5秒に見た目の20mが流れ、8コマ1周期で柵4区間分を通過する。倍率を変えても同じ周期比になる。コースの曲率と羽の位置は共通の物理座標を使い、背景画像は遠景として低速で流す。

中継カメラの追走位置とゴールでの固定位置も前後方向の倍率で換算する。追走中は走路上のすべてが同じ速度で後ろへ流れ、カメラ固定後はすべて止まり、チョコボが同じ相対速度で前へ進む。ゴール付近だけ走行速度が変わることはない。ゲートの見た目の寸法は維持する。停止・巻き戻しは同じ座標から再計算する。

入線後も共通の `visualSample` に従って減速する。ゲート待機・停止中は走行素材の1コマを静止表示する。表彰では `v5/podium/` の専用ポーズを使い、正面待機から左右に片羽を上げて声援へ応える。

試走ページの直線、直線→カーブ、カーブ、カーブ→直線のボタンは、実際の境界の前後50mを基準に走行記録の時刻へ移動する。区間が存在しない短距離ではそのボタンを無効にする。本編では場面送りとシークバーを用い、区間比較用のボタンは表示しない。曲線と直線は共通コースの連続した形状を描く。中継・追走・全景・ゴールの表示と全周ミニマップを用意し、画面外の羽には番号を表示する。小さい画面ではミニマップを時計と順位の下に配置する。

中継カメラはゲートインから発走直後まで固定する。ゲートを進行と反対側の端から約15%の位置に置き、先頭が進行側の端から約1/3まで進んだら、同じ構図から追走を始める。ゴールではラインを進行側の端から1/3の位置に固定し、入線後に少し走り抜ける様子と後続の入線を映す。先頭はそのまま画面外へ走り抜ける。右回りは左右を反転する。固定位置と追走への切り替えは画面幅と描画ピッチに応じて計算し、巻き戻すと各時点の固定・追走位置へ戻る。手動の「ゴール」も同じ構図を使う。ゲートは各出走レーンの発走位置に固定し、発走から0.45秒で左右の扉が前へ開く。発走後8秒まで描き、カメラが通り過ぎるまで走り出す様子を見せる。

時計、再生操作、順位、実況、音声とイベント処理は `race-playback.js` を2D・3Dで共有する。各描画方式は終了時に描画ループと固有の資源を解放する。

## 観戦の操作

1倍速は実際のレース時計と同じ速度。パドックは冒頭6秒＋出走羽1羽につき16秒（12羽なら3分18秒）、ゲート6秒、レース、決着8秒、勝利時の表彰16秒を順に再生する。
一時停止、0.5 / 1 / 2 / 4倍速、再生位置、場面送り、中継・追走・全景・ゴールのカメラ、注目羽を選べる。

## 結果と記録

`ranch-race.js` の全羽共通の時計で計算した約2秒間隔の前後・横位置・速度・行動と最後の入線サンプルを `race-replay.js` で記録。横移動の開始・停止・速度変更時も追加で記録する。
内部の処理は `RanchRace.simulate` → `RaceReplay.capture` → `RaceReplay.frame` → 2D・3D描画の順とする。シミュレーションはDOMや描画方式に依存せず、内寄せ・進路回避・距離ロス・入線を一度計算し、その走行記録を保存する。
`RaceReplay.frame(record, track, time)` は記録と再生時刻から、各羽の連続した横位置・進行距離・メートル座標・進路方向・確定順位を返す。2D・3Dは `RacePlayback.readFrame()` で同じフレームを受け取り、投影・モデルやスプライト・演出を描く。フレーム生成はDOM、カメラ、倍速、描画ピッチに依存せず、入力も変更しない。表示中にレースを再計算したり、ギル・成績・乱数を更新したりしない。
入線時刻、着順、完走の有無は確定結果を使う。複数の自家牧場の羽が出走しても共通のフィールドを保存する。
コースは各競走場の周回距離・直線長・左右の向きを使った3Dの楕円形。1ワールド単位＝1m。
チョコボはモデルの実測高から2.5mに正規化し、コース幅は50m（20体分）。直線では20m/sで毎秒8体分進む。
直線の85%の位置にゴールを置く。距離の基準線は内側。ゲート番号は固定し、走行中の横位置は記録された連続値を使う。コーナー前の内寄せと終盤の進路確保を表示し、斜行中のモデルの向きも進路に合わせる。外側の弧長と横移動による距離ロスは確定結果の計算にも反映する。シミュレーションと描画は `race-course.js` のコース寸法を共有する。

入線後の描画は、入線速度で2秒駆け抜けてから6秒かけて滑らかに減速する。確定距離・時計・順位や保存済みサンプルは変更しない。未完走の羽の走行は延長しない。
「中継」はコース脇の定点カメラからパン・ズームし、最終コーナーは直線側から迎える。最後の直線を追ったあと、最初の入線2.5秒前にゴール面の真横へ切り替え、全羽の入線後に走り抜ける様子を捉える。左右のコースで撮影位置を反転する。

走行記録は各競走結果の任意フィールド `replay`。走行記録のない戦績は結果だけを表示し、存在しない走行を再現しない。
保存時はフィールドと走行記録を重複排除し、`raceFields` / `raceReplays` にまとめる。読込時に通常の配列に戻す。
旧v4の保存形式・走行記録のない戦績も読み込める。横位置付きの走行記録はversion 2。version 1の4要素サンプルは従来の固定レーンで再生し、横位置が保存されていない旨を画面に表示する。存在しない横移動は補わない。バックアップ読込では記録の時刻、距離、横位置、速度、ゲート、色、入線結果との一致を検証する。

## 実況と表彰

パドックでは番号順に全羽を紹介する。2Dは `v5/walk/` の専用歩行8コマを6fpsで再生し、1羽を大きく映す。舗装と柵が後方へ流れる追従映像で、レースの描画ピッチとは独立。3Dも同じ紹介時刻に合わせて環内の1羽を映す。「前の羽」「次の羽」「発走へ進む」で移動でき、パドック中の「注目羽」選択もその羽の紹介開始へ移動する。紹介順はカメラの種類によらず番号順で、倍速・停止・巻き戻し・2D/3D切替で時刻と字幕が一致する。試走ページはパドックから開始し、`?phase=race` ではレース開始10秒後から確認できる。

実況は番号・名前・年齢・性別・出走前の戦績を紹介し、4秒後に解説が長所・短所または脚質・勝算を話す。能力8種の長所32文、短所24文、脚質9文、勝算25文と調子・疲労・馬場の指摘を組み合わせる。文面はレースと紹介順から決定し、巻き戻しても変わらない。勝算は距離に応じた能力の重み、調子、疲労、馬場の適性、気性を使った相対評価。数値的な勝率を表示せず、有力・上位争い・混戦・伏兵・苦戦などの表現に変換する。確定順位、入線時計、走行サンプルを予想の入力には使わない。

新しい出走は `raceEntry` で出走前の能力・気性・調子・疲労・馬場適性・年齢・性別・戦績を複製し、走行記録内の任意の `runner.paddock` に保存する。保存後に調教や成績が変わっても解説に影響しない。旧記録も全羽を紹介し、資料のない羽には一般的な解説を使う。一部の羽だけに出走前資料がある場合も、全体の勝算比較は行わない。読込時は保存した能力などの値域を検証する。

歩行素材の原画・意味領域マスク・金色の素材は内蔵 image_gen で作成。左右の接地と振り出しを確認してv2原画を採用。`assets/chocobo-sprite-study/PROMPTS-walk-v2.json` に最終プロンプトを保存。再構築は `node tools/build_chocobo_sprites.cjs 5 walk`、レイヤーの寸法・色領域・共通部位・アルファ検査は `node tools/validate_chocobo_walk.cjs`。素材プレビューは `/chocobo-sprite-preview.html?motion=walk`。

ラミアが実況、サハギンが解説。字幕はパドック・出走・先頭交代・競り合い・スパート・入線・結果・表彰に合わせて切り替わる。
「実況音声」でブラウザの日本語読み上げを有効にする。日本語音声・声質はブラウザとOSに依存し、専用声優の録音ではない。
2人は読み上げのピッチ・速度を変える。先に読み上げていた発話は切替時に取り消し、倍速で待ち行列が溜まらないようにする。
観戦を閉じると音声・描画ループ・イベント・GPU資源を解放する。ページから離れたときも破棄し、ブラウザの戻る操作でページが復元される場合は観戦状態を復元する。非表示タブでは一時停止し、動きを減らす設定の場合も停止状態から始める。2Dの背景・スプライト・素材一覧はページ内で再利用し、別のレースを開くたびに読み直さない。失敗した素材は次回の観戦で再取得する。

自家牧場の出走羽が完走して1着の場合のみ、表彰台で翼を振る。

2D表彰用スプライトは正面寄りの待機、やや右を向いてくちばしを少し開き右羽を上げるポーズ、正面へ戻る移行の4コマと、その完全な左右反転を組み合わせる。本体10色・額羽6色の独立透過レイヤーで通常走行と同じ60通りに対応。`motions.podium.frameSequence` を5fpsで再生し、待機・挨拶を各0.6秒保持する3.2秒ループ。コース方向の追加反転は行わず、足元の共通アンカーで接地位置を合わせる。再生時計からポーズを選ぶため、一時停止・速度変更・巻き戻しでも再現する。

原画・意味領域マスク・金色の光沢は内蔵 `image_gen` で作成し、プロンプト全文を `assets/chocobo-sprite-study/PROMPTS-podium-v1.json` に保存。再構築は `node tools/build_chocobo_podium.cjs`、検査は `node tools/validate_chocobo_podium.cjs`。素材プレビューは `/chocobo-sprite-preview.html?motion=podium`。

重賞ではカメラのフラッシュ、クラッカーの噴射、舞い落ちる紙吹雪が加わる。撮影台と植栽は通常戦から表示する。
チョコボは同梱のv3モデルを優先し、羽色・額羽・虹の額羽・左右のカーブを反映する。v3のない環境では従来v2モデルを使う。
