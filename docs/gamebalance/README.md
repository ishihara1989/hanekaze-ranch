# 距離適性の実験モデル

元の考察：[gamebalance_GPT.md](../gamebalance_GPT.md)。本ページは独立したシミュレーションを説明する。v4の新進行では共通の身体変換・物理を遺伝・育成・保存へ接続した。[接続範囲](../OPENING_REDESIGN.md)・[序盤検証](OPENING_VALIDATION.md)を参照。実験プリセットと旧セーブはそのまま独立している。

ゲーム能力への対応は [能力・遺伝・調教の設計案](ATTRIBUTE_MAPPING.md) と [生成個体の試走結果](MAPPING_RESULTS.md) を追加。新案の生成個体は脚疲労コストを必ず正にする。性格・管理・馬場・調教は設計案で、身体能力の変換と単独走までを試作・検証している。

ラボの作戦ルールは、身体能力とペース配分を比較するための実験条件。本編でプレイヤーが選ぶ走行指示には使わず、レースではチョコボ自身が性格と隊列から判断する。

羽房最大レベルで他牧場の種牡羽との配合を繰り返す遺伝能力の確認は `npm run balance:breeding -- --write`。[反復配合の検証結果](BREEDING_VALIDATION.md)を参照。既存のNPC履歴キャッシュが必要（未生成なら `npm test` で準備）。監査自体はレースを回さず、固定市場で期待能力最大の相手を選び、各試行で娘1羽を次の母にする。

他牧場の世代交代と種牡羽市場更新を含める場合は `npm run balance:breeding:years -- --write`。[世代交代を含む検証結果](EVOLVING_BREEDING_VALIDATION.md)を参照。NPCの勝敗は遺伝8能力の平均順位で代用し、親選び・年齢・市場更新は本番処理を使う。3年ごとに配合し、娘が3歳になる年のG1相手と比較する。

各G1の実レース確認は `npm run balance:g1 -- --write`。[各G1の3試行結果](G1_RACE_VALIDATION.md)を参照。2・10世代目の牝羽を各母系列1羽ずつ使い、全37G1をそれぞれ3試行。潜在能力と適性を保持し、調教95%、年齢2・3・5歳の本番現在能力で対戦する。背景のNPC世代交代は遺伝順位による近似、対象G1は本番物理と勝利記録で確認する。

- 画面：7羽×7距離の時計と着順、4種類の推移グラフ、400mラップ、個体パラメータの編集、平地／起伏、4つのペース配分、JSON保存。追加の「ユウナギ・2400mで比較する」ボタンで、巡航→スパートが速くなる例を比較できる。
- [巡航→スパートの実測例](PACING.md)：`compare-pacing.cjs --write`（npmでは `npm run balance:pacing`）で再生成。元の7羽とは別の個体・独立した比較。「選択中の羽にこの例の設定を適用」で編集画面でも試せる。

- 初期例は1200・1600・2000・2400・2800・3200・3600mの各距離で、それぞれ1羽が最速となる。これはこの7羽・平地・後述の探索条件での相対的な得意距離。近隣距離でも2位になる例はあり、他の相手やコースに対する保証ではない。

## モデル

体重で割った単位を使用する。速度vはm/s、出力はW/kg、予備容量WはJ/kg、推進力FはN/kg。脚疲労Lは0〜1。数値はゲーム用の仮定であり、動物の生理や実際の競走記録を再現する校正は行っていない。

状態は `speed, aerobic, reserve, fatigue` に走行距離・時刻・診断用の積算値を加えたもの。

### 走行負荷と有酸素供給

平地の必要出力は `P(v) = linearCost × v + cubicCost × v³`、抵抗は `linearCost + cubicCost × v²`。有酸素供給の上限 `Amax = P(criticalSpeed)` は巡航速度から導出し、独立した矛盾のある値を設定しない。

現在の有酸素出力Aは、要求出力とAmaxの小さい方へ時定数 `cardioTau` で追従する。指数更新 `Anew = target + (Aold − target) exp(−dt/tau)` で立ち上がる。発走時は `Amax × initialAerobic`。立ち上がり中の不足もWから支払う。

### 加速・坂とW

作戦が目標速度を要求し、1.5秒の追従時間で要求加速度を算出する。要求推進力は `抵抗 + 9.81 × slope + 要求加速度`。斜度は2.5%なら0.025。上りでは必要出力が増え、下りでは減る。

実際の力は要求値、疲労後の最大推進力、供給可能出力のすべてで制限する。出力は `F × v`、供給上限は `A + min(anaerobicPower, W/dt)`。静止発走の加速が無料にならないよう、出力の計算には予測したステップ中間速度（最小0.5m/s）を使用する。加速は `a = F − 抵抗 − 9.81 × slope` から求める。目標速度が下がったときには制動を加え、最高速は `maxSpeed` で制限する。

実際の使用出力がAを超えた分だけWを減らす。Aが余れば `recoveryRate` 倍だけゆっくり回復する。Aはステップ前後の平均値を使用する。容量は0〜`reserveCapacity`。容量が大きくても `anaerobicPower` が低ければ短時間に使い切れない。

`fatigueCost=0` なら定常状態で巡航以下の走りはWを消費しない。一方、絶対的な消費エネルギー `energyUsed` と脚への負荷は残る。「有酸素で賄える」と「無消耗」は異なる。`fatigueCost>0` の個体は疲労すると同じ速度に必要な出力が増え、疲労前の巡航速度以下でもWを使うことがある。`criticalSpeed` は疲労前の基準値である。

### 脚疲労

```
dL/dt = ((F/4)³ + 0.04 × max(a,0)² + 0.03 × max(−slope,0) × v²) / legEndurance
        + anaerobicFatigue × 無酸素エネルギーの使用出力 / reserveCapacity
Fmax_eff = max(linearCost + 0.15, maxForce × (1 − 0.88 × L²))
使用出力 = F × ステップ中間速度 × (1 + fatigueCost × L²)
```

高い力・加速・下りの衝撃でLが増え、力の上限が非線形に下がる。Lは0〜1で、レース中の回復は入れていない。`legEndurance` は固定の基準負荷4N/kgに対する耐久時間であり、「その秒数で必ず失速する」という意味ではない。最大推進力の高い個体に自動で高い耐久が付かないよう、基準負荷は全個体共通。

疲労しきっても平地で低速の移動を続けられるよう、小さな力の下限を置く。厳しい坂や極端なパラメータでは時間内未完走も起こりうる。最大1200秒で打ち切り、`finished:false, time:null`、順位なしとして扱う。

W不足は高出力の持続を制限し、Lは推進力・加速を制限する。Wが残っていてもLが高ければスパートできない。

### 追加した2つの交換条件

元のモデルで早い段階の疲労が効くのは、主に推進力上限が要求値を下回った後だった。数値を広く探索しても、巡航→終盤加速が細かく調整した一定ペースに明確に勝つ例を見つけられなかったため、次の2パラメータを追加した。

- `anaerobicFatigue`：予備容量を1回分使ったときに加算される脚疲労。Wを使うほど脚も疲れる。
- `fatigueCost`：L²に対する走行コストの増加係数。要求出力、供給出力から出せる力の計算、実際のW消費に同じ係数を適用する。無料で加速したり、同じエネルギーを二重に課金したりしない。

早くWを使うと、残り区間も効率の落ちた脚で走ることになる。終盤に使えば高い走行コストを負う時間が短い。この持続する負担からスパートのタイミングに意味が生まれる。追加個体はゲーム用の仮説を確かめる例であり、現実の生理モデルとして校正したものではない。元の7羽の初期値は両方0なので、従来の距離別の結果は変わらない。

## パラメータと距離適性

[balance-presets.js](../../public/js/balance-presets.js) に7羽分と追加の作戦比較個体を定義。[実測結果](RESULTS.md) に共通値を含む全13パラメータを掲載している。

短距離型は最高速・瞬間出力・推進力・心肺の立ち上がりに優れるが、巡航力と脚の耐久が低い。長距離型は巡航力・容量・脚耐久を上げ、最高速・放出出力・推進力を下げた。容量だけを増やすと全距離で有利になりやすいため、独立した複数の能力を交換条件にしている。中間型は両側の相手に異なる理由で負ける。

`exampleDistance` は画面表示と検証用のメタデータ。物理モデル・ペース配分・探索器はこの値も個体名も読まない。レース距離はゴールとスパートを始める位置にのみ使用し、距離適性倍率・目標距離からの罰則・個体別の距離依存式はない。

## 比較条件と作戦

- 乱数なし・静止発走・共通の刻み0.1秒。単独走の時計を順位に変換する。接触・進路取り・風よけ・相手への反応は未実装。
- 平地のほかに、1200m周期で300〜600mが+2.5%、750〜1050mが−2.5%の起伏コース。区間定義はレース全長で伸縮しない。
- 共通候補探索：巡航倍率0.85〜1.40を0.025刻み（23通り）×スパート開始の残距離0・200・400・600・800・1200m（6通り）＋発走から全力の計139候補。全個体・全距離で同じ候補を使う。
- 最速は有限候補内での結果であり、全てのペース配分に対する大域的最適解ではない。今回の各得意距離では発走から最高速を要求する作戦が最速だった。実際の速度は加速・出力・疲労で制限される。序盤を抑える作戦が常に有利となるような設定は入れていない。
- 手動比較用：巡航→残り400m、同じ作戦に序盤35秒の巡航倍率+0.35を追加、発走から全力、の3種類。
- 追加の作戦比較では倍率0.65〜1.45（0.005刻み）、スパート残距離50〜距離未満（50m刻み）で詳しく探索する。一定の目標速度も同じ細かさで探索し、発走から全力・序盤35秒だけ飛ばす作戦と比較する。距離別の直接補正はなく、全候補に同じ物理式を使用する。
- ヒバナ2800mでは序盤を飛ばすと最初の400mは約6秒短縮するが、最後の400mで大きく失速し、全体では約23秒遅くなる。短い適距離なら全力が有利なので「飛ばす＝必ず不利」でもない。
- 距離積分は台形則。ゴールと400m通過時刻はステップ内補間し、刻みの端まで余計に走らせない。刻みを0.05秒にしても全7距離の最速個体が一致することをテストする。
