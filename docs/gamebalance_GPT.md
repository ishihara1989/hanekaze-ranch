重要なのは、**「スタミナ＝1本のHPゲージ」にはしない**ことです。おすすめは、

- 有酸素能力＝継続して供給できる「出力」
- 無酸素容量＝その出力を超えたときに使う有限の「予備タンク」
- 脚疲労＝高出力・加速・坂などで蓄積する別の疲労

の3要素です。

## 1. 「ベーススピード」は Critical Speed と考える

ユーザーのいうベーススピード \(v_c\) は、かなりそのまま **Critical Speed** に対応させられます。

現実のCritical Speedモデルでは、

> CS以下 → 代謝的に定常状態を維持できる  
> CS以上 → 有限の予備エネルギー \(D'\) / \(W'\) を消費する

という扱いになります。しかも一定速度で単純化すると

\[
t_{\rm limit} = \frac{D'}{v-v_c}
\]

のような双曲線になるので、最初から非線形です。2026年のレビューでも、CSは最大代謝定常状態、D′はCSを超えて使える有限容量として整理されています。:chatgpt-content-reference{index="0"}

ゲームではもう少し物理寄りに、

\[
P_{\rm crit}=P(v_c)
\]

と置くのが特におすすめです。

たとえば平地で必要な出力を

\[
P(v)=c_1v+c_3v^3
\]

とします。

すると、

**遅いチョコボ**

\[
v_c=15
\]

**速いチョコボ**

\[
v_c=18
\]

なら、速いチョコボは当然

\[
P(18)>P(15)
\]

だけのエネルギーを毎秒使っています。

しかし速いチョコボには

\[
P_{\rm crit}=P(18)
\]

だけの有酸素供給能力があるので、18で走っても有限スタミナは減らない。

一方、遅いチョコボを18まで無理やり走らせると

\[
P(18)-P(15)
\]

の不足が生じ、それを無酸素容量から補います。

これはまさに、

> ベース速度が速いチョコボは絶対的にはたくさんエネルギーを使うが、その速度に身体が対応している。  
> 遅いチョコボが同じ速度を出すと無理をしているのでスタミナを削る。

という欲しい性質になります。

しかも \(v < v_c\) なら有限スタミナをほぼ消費しないので、

> ベーススピードより遅く走れば、元からその速度がベースのチョコボと似た消耗

も自然に実現できます。

# 2. 「心肺スタミナ」はタンクではなく供給能力にする

ここはかなり重要です。

酸素そのものを「残り100 → 0」というタンクにするより、

\[
P_{\rm aerobic}
\]

という**毎秒供給できるエネルギー量**にする方がいいです。

さらに現実には酸素摂取量は一瞬では最大になりません。

競走馬をモデル化した研究でも、スタート後しばらくは \(\dot VO_2\) が上昇し、モデル上ではおよそ20～30秒・約400mほどで高い水準に到達しています。このため序盤では無酸素エネルギーの使用量が大きくなります。:chatgpt-content-reference{index="1"}

これを

\[
\frac{dA}{dt}
=
\frac{A_{\rm target}-A}{\tau_{\rm cardio}}
\]

とすると非常に面白くなります。

ここで

- \(A\): 現在の有酸素供給出力
- \(A_{\max}\): 最大有酸素出力
- \(\tau_{\rm cardio}\): 心肺の立ち上がり速度

です。

つまりスタート直後、

\[
A \ll A_{\max}
\]

なので、いきなり全力を出すと不足分を全部無酸素系から支払う。

これだけで、

**序盤から飛ばす → 一応速い → しかし終盤用の予備タンクをかなり削る**

という挙動が自然に発生します。

# 3. 無酸素容量を「スパート用タンク」にする

状態変数を

\[
W \in [0,W_{\max}]
\]

とします。

必要出力を \(P_{\rm req}\) とすると、

\[
\frac{dW}{dt}
=
-\max(0,P_{\rm req}-A)
\]

基本はこれだけです。

つまり

\[
P_{\rm req}=700
\]

なのに現在の有酸素供給が

\[
A=500
\]

なら毎秒200ずつ予備容量を削る。

逆に楽をしているときは多少回復させてもよいです。

\[
\frac{dW}{dt}
=
r\,(A-P_{\rm req})
\]

ただし

\[
r \ll 1
\]

として回復はかなり遅くします。

Critical Power系でも、閾値以下では \(W'\) が再構成されるモデルが研究されています。:chatgpt-content-reference{index="2"}

# 4. 「乳酸ゲージ」は作らず、脚疲労を別にする

ここは現実寄りにするなら少し注意が必要です。

「乳酸が溜まるから脚が動かなくなる」という昔ながらの説明は単純化しすぎです。乳酸そのものは代謝にも利用されます。一方、高強度運動では急速な糖代謝、酸塩基状態の変化、筋収縮能力低下などが疲労に関係します。馬でも、高強度運動と長時間運動では疲労のメカニズムが異なります。:chatgpt-content-reference{index="3"}

ゲーム上はまとめて

\[
L = \text{Leg Fatigue}
\]

でよいと思います。

例えば、

\[
\frac{dL}{dt}
=
k_f
\left(\frac{F}{F_{\max}}\right)^p
+
k_a\max(a,0)^2
+
k_u\max(slope,0)^2v
\]

とします。

特に

\[
p=2\sim4
\]

くらいがおすすめです。

つまり80%出力を長時間使うのと100%出力を使うのでは、単純な1.25倍ではなく、

\[
0.8^3=0.512
\]

対

\[
1^3=1
\]

くらい違う。

これがかなり重要な非線形性になります。

# 5. 疲労すると何が落ちるか

脚疲労 \(L\) を単なる第二のスタミナゲージにせず、**力を出せなくなる原因**にします。

例えば、

\[
F_{\max,\rm eff}
=
F_{\max}
(1-k_LL^q)
\]

そして

\[
a_{\max}\propto F_{\max,\rm eff}
\]

とします。

すると脚を使いすぎたチョコボは、

- 最高速度そのものより
- 加速できない
- 坂で踏ん張れない
- ラストスパートを開始しても伸びない

という状態になります。

これが非常に競馬らしい「脚を使ってしまった」表現になります。

一方 \(W\) がなくなると、

**高出力を有酸素系だけで賄わなければならない**

ので自然に

\[
v\rightarrow v_c
\]

付近まで落ちていく。

したがって、

**W不足 → スパートを維持できない**

**脚疲労 → スパートそのものが出ない**

と違う挙動にできます。

これはゲーム的にもかなり面白い区別です。

# 6. 上り・下り・加速

ここも実際の力学をかなりそのまま利用できます。

### 上り

傾斜 \(s\) に対して追加出力を

\[
P_{\rm hill}
\approx mgvs
\]

とする。

つまり、

**坂 × 速度**

で急激にきつくなります。

実際のサラブレッドでも、上りでは酸素消費量・心拍出量が増え、下りでは酸素消費量が低下することが確認されています。:chatgpt-content-reference{index="4"}

### 加速

\[
P_{\rm accel}
=
mav
\]

の正の部分を追加します。

\[
P_{\rm req}
=
P(v)+
\max(0,mav)+
\max(0,mgvs)
\]

これで、

**15→18m/sに一気に加速**

と

**最初から18m/sを維持**

が全く違う負荷になります。

競走馬の数理モデルでも、速度・推進力・無酸素エネルギーを別の状態変数として扱い、推進力を瞬時に変えられない制約まで入れています。:chatgpt-content-reference{index="5"}

### 下り

心肺負荷は軽くする。

ただし、

**脚疲労までゼロにしない**

のがおすすめです。

下りでは位置エネルギーを身体側で受け止める必要があり、競走馬はエネルギー的には下りが楽でも、実際には単純に下りほど高速化するわけではありません。:chatgpt-content-reference{index="6"}

なので例えば、

\[
P_{\rm req} \downarrow
\]

だが

\[
L_{\rm downhill}
=
k_d|s|v^2
\]

を少し加える。

これなら、

「下りは息が楽だが、高速で突っ込むと脚には少し来る」

というコース攻略要素にもできます。

# 7. 瞬発力＋スタミナ＝短距離最強、を防ぐ

ここはシミュレーション設計上かなり重要です。

**「瞬発力」と「スタミナ」だけでは、両方高い個体は当然短距離でも強くなります。**

これは数式を工夫しても本質的には避けられません。

そのため少なくとも次の能力を分離した方がいいです。

| 能力 | 意味 |
|---|---|
| \(v_c\) | 巡航速度 / Critical Speed |
| \(A_{\max}\) | 有酸素最大出力 |
| \(W_{\max}\) | 無酸素容量 |
| \(P_{\rm anaerobic,max}\) | 無酸素エネルギーを一気に使える最大速度 |
| \(F_{\max}\) | 最大推進力 |
| \(v_{\max}\) | 機械的な最高速度 |
| \(\tau_{\rm cardio}\) | 心肺立ち上がり |
| \(R_L\) | 脚疲労耐性 |

特に、

## 「容量」と「出力」を分ける

のが非常に効きます。

巨大なバッテリーでも放電速度が低ければ瞬間的に大電力を出せないのと同じです。

たとえば、

### 短距離型

\[
v_c=16,\quad
W=70,\quad
P_{\rm anaerobic,max}=100,\quad
v_{\max}=22
\]

### 長距離型

\[
v_c=18.5,\quad
W=100,\quad
P_{\rm anaerobic,max}=45,\quad
v_{\max}=20
\]

なら、長距離型はスタミナも大きく瞬発用エネルギーも大量に残せる。

しかし一度に45しか吐けないので、

**ラスト200mだけなら短距離型の方が速い。**

これはかなり自然な距離適性になります。

# 8. 距離適性を直接パラメータにしない

このシステムなら「短距離A・長距離C」みたいな隠し補正を持たせなくても、

パラメータの組み合わせから勝手に適性距離が発生します。

例えば、

**短距離型**
- 低めの \(v_c\)
- 高 \(v_{\max}\)
- 高 \(P_{\rm anaerobic,max}\)
- 高 \(F_{\max}\)
- 中程度の \(W\)

**マイル型**
- 中程度の \(v_c\)
- 高 \(W\)
- 高めの無酸素出力

**中距離型**
- 高 \(v_c\)
- 高 \(W\)
- 中程度の最高速

**長距離型**
- 非常に高い \(v_c\)
- 高い脚耐久
- 大きな \(W\)
- 最高速・瞬間放出出力はそこそこ

という形になります。

そして、

**「2000mでは強いが1200mだとスピード不足、3000mだと脚が保たない」**

という中距離馬も普通に作れます。

# 9. 非線形性は3か所に入れるのがおすすめ

「全部一次式だと端点が最適になる」という感覚はその通りです。

ただ、複雑な式を大量に入れる必要はありません。

私は次の3か所だけ非線形にします。

### ① 速度と必要出力

\[
P(v)=c_1v+c_3v^3
\]

高速になるほど速度1m/s増加の代償が大きくなる。

### ② 脚疲労

\[
\dot L\propto
\left(\frac{F}{F_{\max}}\right)^3
\]

高出力を続けるのが極端に悪い。

### ③ 疲労による能力低下

例えば

\[
F_{\max,\rm eff}
=
F_{\max}(1-L^2)
\]

としておけば、

疲労50%では

\[
75\%
\]

の力を出せるが、

疲労90%では

\[
19\%
\]

しか出せない。

これによって「少しオーバーペース」なら耐えられるが、「限界を超えて逃げ続ける」と最後に一気に沈む挙動が作れます。

# 10. 私なら最終的にこの状態だけ持たせる

シミュレーションtickごとの状態としては、

\[
\boxed{
(v,\ A,\ W,\ L)
}
\]

だけで十分だと思います。

- \(v\): 現在速度
- \(A\): 現在の有酸素供給出力
- \(W\): 残り無酸素容量
- \(L\): 脚疲労

チョコボ固有値は、

\[
\boxed{
v_c,\quad
v_{\max},\quad
A_{\max},\quad
W_{\max},\quad
P_{\rm anaerobic,max},\quad
F_{\max},\quad
\tau_{\rm cardio},\quad
R_L
}
\]

程度。

そしてAI/騎手は「速度」を直接指定するのではなく、

\[
u(t)=\text{要求推進力}
\]

あるいは「目標速度」を指定して、それをPID的に推進力へ変換する。

実際の速度は、

\[
m\frac{dv}{dt}
=
F_{\rm propulsion}
-F_{\rm resistance}
-mg\,slope
\]

から決める。

この構造にすると、**上り坂で同じ指示を出しても自然に速度が落ちるし、無理に速度を維持しようとするとWと脚を大量に使う**ようになります。

実際に競走馬を対象にした研究でも、ほぼ同じ発想で「速度・推進力・有酸素供給・無酸素エネルギー・坂・コーナー」を連立方程式として扱っています。かなり今回のゲームの参考資料として直球です。:chatgpt-content-reference{index="7"}

特に面白いのは、そのモデルでも**序盤の強い加速で無酸素エネルギーを使い、途中は有酸素系主体、最後に再び無酸素系を大きく使う**形が出ています。:chatgpt-content-reference{index="8"}

この方式なら、ユーザーが挙げた「逃げ馬がリード維持のため予定以上に脚を使う → 最終コーナーでまだ先頭 → 直線に入ったところで \(W\) は残っているのに \(L\) が高すぎて加速できず沈む」みたいなレースまで、かなり自然に発生させられると思います。

次に設計するなら、**具体的に1200m / 1800m / 2400m / 3200mで異なるタイプのチョコボがクロスオーバーするような数値を入れて、Pythonでこの4状態モデルを実際にシミュレーションできるところまで落とす**のがよいです。そこまでやると各パラメータがレース展開にどう効くかかなり見えてきます。
