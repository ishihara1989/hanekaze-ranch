# 羽風牧場 / WING & WIND — v0.4

シロマと一緒にチョコボを産み、育て、競走へ送り出すブラウザの牧場ゲーム。レースでは育てたチョコボを信じて見守ります。ペース・スパート・進路はチョコボ自身が能力・性格と周囲の状況から判断します。

## 起動

```powershell
node server.cjs
```

**http://127.0.0.1:4173** を開きます。Node.js以外の依存パッケージは不要です。

[源流の遺伝情報・公開段階プレビュー](http://127.0.0.1:4173/genetics-preview.html) では32羽の源流と4公開段階を切り替え、並べて比較できます。セーブデータには触れません。`public/genetics-preview.html` を直接開くこともできます。

## 遊び方

1. 牧場名と冠名（1〜7文字のカタカナ）、冠名を前・後ろのどちらにつけるかを設定。3月第1週、瞬発力が持ち味の2歳牝羽1羽、20,000 Gからスタート。競走羽はモーグリの自動管理済み。シロマの案内で繁殖牝羽セールへ。
2. 繁殖牝羽を1羽迎え、種牡羽の一覧から配合。配合期間は3月第1週〜4月第4週で、遺伝効果の予測を5段階の範囲で確認できます。4週後に誕生します。セールへのリンクはトップページにもあります。
3. 「次の週へ」で成長を見守ります。報告はモーダルで開き、元の画面を保ったまま閉じたり、続けて週送りしたりできます。「4週まとめて進める」は月報・イベントと4週分のダイジェストをまとめて表示。名前登録が必要な週で停止します。
4. 2歳になる年の1月第1週に名前を登録し、「着実に勝つ / 重賞に挑む」を選択。名前は2〜9文字のカタカナ（長音「ー」も可）。性別に合う名前の候補が最初から入り、自由入力も可能です。登録後は改名できません。モーグリが調教・休養・出走を担当します。
5. 必要なときだけチョコボ・配合・施設・牧場手帳を開きます。1歳以下は成長率、2歳以上は現在ステータスを5段階で確認できます。繁殖担当は遺伝効果を合算して評価します。レース初勝利で研究所が解放され（建設2.5万G）、羽場や成長などの遺伝と競走情報、一方の記念施設で全遺伝の座位、記念館と銅像の両方で現在能力の数値を含む全情報が公開されます。

初年度に生まれた子は3年1月に2歳登録。年齢は1月に一斉加齢する暦年制です。週報の「2Dでレースを見る」から、パドック→出走→レース→決着→勝利時の表彰を観戦できます。全6競走場の背景と羽色・額羽を反映した2D画面が標準です。実況ラミア・解説サハギン、実況字幕と任意の日本語音声、倍速・一時停止・カメラ切替に対応。戦績と過去の報告からも見返せます。走行データの記録はこの機能の追加後の出走からです。

設定の **セーブ・ロード** には、オートセーブとは別の手動セーブスロットが5つあります。各スロットに保存日時・ゲーム内の日付・所持ギル・所有羽数を表示します。保存済みスロットへの上書きとロードは確認画面で確定します。ロードすると現在の牧場とオートセーブがその記録に置き換わります。週送り・オートセーブ・リセットでは手動スロットは変わりません。

自動保存・手動セーブはブラウザの **IndexedDB**（データベース `hanekaze-ranch`、ストア `saves`）に保存します。以前のlocalStorageのv4自動保存・5スロットは初回起動時にまとめて移行し、元データはバックアップとして残します。移行済みのデータを古いバックアップで上書きすることはありません。保存完了を待って操作を再開し、別タブとの競合も検出します。保存は同じブラウザ・プロファイル・URLに紐づき、JSONの書き出し・読み込みも引き続き使えます。

手動ロード・JSON読込・ページの再読み込みで再開すると、その先の孵化やレースなどの抽選は新しく行われます。同じ孵化前のセーブから再開しても、子の遺伝・能力・性別は固定されません。すでに生まれた羽の情報や記録済みの孵化報告・レース結果は、セーブどおりに復元します。

設定の **セーブをリセット** で序盤を再体験できます。牧場名・冠名・前後の位置を再設定し、確認ダイアログで確定するまで現在のデータは変わりません。保存は操作ごとに自動実行。JSONの書出し・読込にも対応します。設定のない既存のv4セーブは「羽風牧場・ハネカゼ・前につける」を引き継ぎます。

名前のもとは牡340語・牝370語。牡は速度・力・猛獣など、牝は花・宝石・音楽などを中心に、9割以上を5文字以下にしています。他牧場の競走羽や血統の元になる羽も、性別に合うストックと冠名から命名します。9文字以内に収まるストックを使い切った場合だけ、カタカナを機械的に組み合わせます。冠名を短縮することはありません。

現役競走羽、供用中の種牡羽、血統に残る牡羽、当年を含む直近20年のGⅠ勝者、源流・始祖、殿堂入りの名前は再使用できません。幼羽の候補も予約し、同時登録の重複を防ぎます。これらに該当しなくなった引退羽の名前は再使用できます。命名は遺伝・レース用の乱数を消費しません。

旧版のセーブは考慮せず、新しい保存キーに独立して保存します。v1〜v3のバックアップは新UIには読み込めません。旧キーは削除しません。`localhost` と `127.0.0.1`、異なるポートはそれぞれ別の保存先です。

競走羽の個別画面では、能力150を共通スケールにしたゲージで現在能力・加齢による低下・伸びしろを表示します。伸びしろの右端は各羽の能力上限です。今週から8週分の予定も確認でき、総合・重点調教、休養、出走レースの指定を保存すると週送りに反映されます。体調・出走条件・4週以上の出走間隔を守り、指定できないときは回復や調教を優先します。モーダルの外側クリックやEscapeで閉じられます。

身体8能力・管理2資質・性格6要素に、羽場適性4項目・コーナーと直線の適性3項目・成長3因子・羽色と額羽の遺伝を接続しています。路面とクッションへの適性は接地時の推進効率に作用します。右回り・左回り適性はコーナーの減速と余計な消耗を抑え、直線適性は速度とコーナー出口の推進力を高めます。他牧場も毎週の重賞に出走し、GⅠ勝者を週報に掲載。年10羽・5年契約の種牡羽市場、部門別GⅠポイント表彰に接続しています。多世代のGⅠ難易度は継続調整の対象です。

テストは初回に `npm install`（または `pnpm install`）で開発用依存を入れます。IndexedDBの移行・保存失敗・同時更新の検証に `fake-indexeddb` を使い、ゲームの実行には追加の依存は不要です。

```powershell
node --test tests/*.test.cjs
node tools/audit-opening.cjs --write
```

新UIは `public/js/ranch-ui.js`、進行は `public/js/ranch-engine.js`、スタイルは `public/css/ranch.css`。旧 `game.js` / `world-views.js` は回帰検証用に残し、起動ページでは読み込みません。

一覧・ステータスには画像生成した年齢別ポートレートを使用。0歳は見下ろすヒナ、1歳はやや見下ろす小鳥、2歳以上はやや見上げるクォータービューで額羽の差分を描画します。本体10色・額羽6色に対応し、呼吸と小さな揺れの待機ループ付きです。[年齢・羽色プレビュー](http://127.0.0.1:4173/chocobo-portrait-preview.html)、[素材と生成プロンプト](public/assets/chocobo-portraits/README.md)で確認できます。

距離適性ラボは **http://127.0.0.1:4173/balance-lab.html**、3Dモデル試作は **http://127.0.0.1:4173/chocobo-preview.html**（第3版が既定、羽色10色・額羽6色を切り替え可。詳細は `public/assets/chocobo-v3/README.md`）。独立した実験として引き続き利用できます。

ゲーム内のレース観戦は2Dが標準です。観戦画面の「2D / 3D」で、再生位置・停止状態・倍速・注目羽・カメラ・音声設定を保ったまま切り替えられます。「動き」は足と景色のテンポを選ぶ設定で、既定は「きびきび」。時計・着順・実際の羽同士の位置関係は共通の走行記録に従います。

レースはUIに依存しない内部シミュレーションで一度計算し、内寄せ・進路変更を含む走行記録を保存します。2D・3Dはその記録から同じ再生フレームを受け取って描画します。観戦や巻き戻しでレースを再計算することはありません。

2Dレース試作は **http://127.0.0.1:4173/race-2d-preview.html** に引き続き残しています。競走場・左右の向き・描画ピッチの比較と、直線・カーブへの区間ジャンプはこちらで確認できます。素材一覧は **http://127.0.0.1:4173/race-2d-backgrounds.html**。
